# AGENTS.md

Restaurant + camping management SPA: React 19 / Vite 8 frontend, tRPC 11 over Hono, Drizzle ORM on Postgres (Neon), deployed as one Vercel project (static SPA + `api/index.js` function). Use npm (`package-lock.json`).

## Commands

```bash
npm run dev          # API on :3000 + Vite on :5173 (proxies /api); open http://localhost:5173
npm run dev:backend  # tsx watch server/dev.ts (requires .env)
npm run dev:frontend # Vite only; API calls fail unless the backend is running
npm run build        # vite build + esbuild bundle server -> api/index.js (does NOT typecheck)
npm run format       # prettier --write . (whole repo)
npm run db:push      # push db/schema.ts to Postgres (uses DIRECT_URL)
```

- Typecheck: `npx tsc -p tsconfig.app.json --noEmit` (frontend) and `npx tsc -p tsconfig.server.json --noEmit` (server/db/contracts).
- Do NOT run `npm run check` (`tsc -b`). It is currently broken: root `tsconfig.json` lacks `allowImportingTsExtensions`, so it fails on `src/main.tsx` (TS5097) and still emits `.js` files next to every source file. If it runs, delete those untracked generated `.js` files.
- Lint: `npx eslint <paths>` for touched files. `npm run lint` currently fails with ~42 pre-existing errors (mostly shadcn `src/components/ui/*` fast-refresh rules and `any` in pages); don't mass-fix them or use lint as a gate.
- Tests: none exist. `npm test` exits 1 ("No test files found"). Vitest only includes `server/**/*.{test,spec}.ts`; run one with `npx vitest run server/foo.test.ts`.

## Setup / env

- Copy `.env.example` to `.env`. Required: `DATABASE_URL` (Neon pooled `-pooler` host), `JWT_SECRET`, `OWNER_EMAIL`, `OWNER_PASSWORD`. `DIRECT_URL` is used by drizzle-kit (falls back to `DATABASE_URL`). `MANAGER_*` and `CLOUDINARY_*` are optional; receipt uploads fail with `PRECONDITION_FAILED` when Cloudinary is unset.
- `server/lib/env.ts` validates env with zod at import time; missing required vars crash the server immediately.
- Accounts are created lazily on first login (`server/auth-router.ts` -> `server/queries/users.ts`), not by a seed. `db/seed.ts` is a TODO stub.
- Schema changes: edit `db/schema.ts`, then `npm run db:push`. `db/migrations/*.sql` is gitignored, so generated migration SQL is not committed.

## Architecture

- `server/app.ts` is the Hono app: `/health`, `/api/health`, tRPC at `/api/trpc/*`. `server/dev.ts` is the local server; `server/vercel-entry.ts` is the Vercel handler. Keep its custom Web `Request` construction — Vercel pre-parses the body, and `@hono/node-server`'s listener hangs POSTs there.
- Add API features as `server/<feature>-router.ts` and register them in `server/router.ts` (auth, menu, sales, expenses, camping, reports, data, cloudinary, vendors).
- Use `publicQuery` / `authedQuery` / `adminQuery` from `server/middleware.ts`, never raw `t.procedure`. `publicQuery` retries Neon cold starts: queries retry all transient DB errors, mutations only connect-phase errors so writes are never replayed.
- Auth is JWT via `Authorization: Bearer`; the frontend stores it in `localStorage["auth_token"]` (`src/providers/trpc.tsx`). `contracts/constants.ts` `Session.cookieName` is unused — there is no cookie auth.
- `db/schema.ts` is the DB source of truth; `numeric` money columns are `string` in TS (cast with `Number(...)` when computing). `contracts/types.ts` re-exports schema types.
- Routing lives in `src/App.tsx`. `/reports/{weekly,monthly,yearly,range}` redirect to `/reports?tab=...`, rendered by `ReportsHub.tsx` (the standalone Weekly/Monthly/Yearly pages are not routed). Camping sale create/edit is a modal inside `SalesExpenses.tsx`, not its own route.
- Roles: `admin` = owner (gates owner-only UI and `data` backup/restore); `managerQuery` exists but no router uses it yet — everything else is `authedQuery`.
- Aliases `@` -> `src`, `@contracts` -> `contracts`, `@db` -> `db` are configured in Vite, Vitest, and the tsconfigs.

## Deploy

- `vercel.json`: builds with `npm run build`, serves `dist/`, rewrites `/api/*` -> `api/index.js`, region `sin1`, 30s limit.
- `api/index.js` is generated by `npm run build:api` but tracked in git; never hand-edit it — rebuild instead.
- Backend must stay Node 20-compatible (`esbuild --target=node20`, Vercel `nodejs` runtime).
- Neon pooled connections require `prepare: false` and SSL; see `server/queries/connection.ts`.
